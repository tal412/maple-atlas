1. Build around the map

Classic World’s grand launch was October 21, 2026, following Founder’s Access on October 6. Target that public release explicitly, rather than mixing modern MapleStory or older private-server data. See the official release notes and official Steam announcement feed.

Mapleclassic.xyz already combines valuable map, monster, NPC, quest and routing tools. Retain that connected information. Rebuild the experience around a persistent, full-screen map, with search and context floating above it.

Desktop

A compact From/To panel sits at the upper left. Selecting a place opens a side sheet; selecting directions changes that sheet into the route itinerary. The map stays visible. Search accepts cities, individual maps, NPCs, monsters and quests, with disambiguated results.

Mobile

Use a top search field, reachable map controls and a bottom sheet with collapsed, half and expanded states. Pinch to zoom; tap a marker to inspect; choose “Start here,” “Directions” or “Add stop.” Preserve the selected place when the sheet changes height.

“Live” means responsive routes and progress updates. Location is selected manually; the app does not read the running game or track the character automatically.

2. One visual language, three levels of detail

Use original SVG artwork that respects Maple geography: recognizable coastlines, towns, forests and regional relationships. Material 3 surfaces, typography, rounded sheets, clear selection states and restrained motion keep controls legible. Character artwork remains authentic PNG sprites, not generic character icons.

3. Directions that explain the journey

Users can type endpoints or set them by clicking places. Draw one continuous highlighted route over the same geometry as the visible roads; keep branches subdued. Selecting any route step reveals its contents and incoming/outgoing portal. Show the full intermediate sequence even when a corridor is collapsed visually.

Choose start→Choose destination→Inspect steps→Mark arrival

The verified export route from Lith Harbor to Henesys contains ten maps and nine transitions, including all three Thicket Around the Beach maps, 3-Way Road-Split and the western Henesys fields. Count portal transitions initially. Offer estimated time or cheapest travel only after timings, fares and restrictions have evidence.

Keep edges directed. Preserve alternative portals between the same maps and their named arrivals. Unknown access conditions must remain visible; unavailable destinations should produce a clear explanation. “I’m here now” advances the itinerary manually and recalculates from that map.

4. Make discovery personal

Each character gets a name, level, class and separate quest journal: Not started, In progress, Completed or Skipped. Changes are reversible. Save locally first, with export/import; optional account sync comes later. Completion is user-entered, never inferred from visiting a map.

A “For you” layer ranks useful nearby quests, objectives and stops using eligibility, prerequisites, class, player goals and added travel. Explain each suggestion: “Hunt objective on your route” or “Requires level 20.” Minimum level alone cannot establish eligibility.

Loot recommendations need verified monster-to-item links, class relevance and ownership preferences. Store recommendations need verified inventory. Unknown drop rates stay unknown. Let users add a suggested stop, preview the extra transitions and remove it before starting.

5. Keep geography and evidence separate

246current fixture map records
457directed portal pairs

The fixture combines pinned OSMS export records with community atlas positions. All included type 1/2/3 portal destinations and named arrivals validate; activation conditions are not playtested. Other portal types and destinations outside this fixture remain excluded.

There are 182 maps without published atlas anchors. Preserve them in search and routing. Three forest positions used to connect collapsed corridors are explicitly schematic. They do not become verified anchors. The return-town field homeId is not physical containment; the earlier coordinate inheritance error is fixed.

Model confidence per field: exported record, community position, inferred association or playtested fact. Atlas anchors are approximate community placements, not verified official client coordinates. Quest records may exist before availability; similarly named NPCs require ID-level review. See the public reliability summary and validated portal graph.

6. A practical production architecture

Build with React and TypeScript. Use Leaflet CRS.Simple for the non-geographic canvas and an SVG overlay for original world art. Keep world coordinates, artwork coordinates and local portal coordinates distinct through explicit adapters. Three.js adds little unless a later feature genuinely needs 3D.

Use Base UI for accessible React behavior, with owned Material 3 design tokens and styling. It supplies primitives, not the visual design. Avoid depending on Material Web for the foundation while its official repository states maintenance mode.

Pinned sources→Normalize + validate→Versioned data bundle→Search + route + UI

The published app is a static frontend on GitHub Pages. Character level, selected places and quest statuses are saved locally with IndexedDB. No backend or account is required. Clearing site data clears local progress; a different device has its own save.

Core entities: Map, AtlasAnchor, Portal, NPC, Monster, Quest, Item, ShopInventory, Character and QuestProgress. Use stable IDs; retain source version and confidence. A Portal stores source/destination IDs, arrival names, alternatives, conditions and nullable costs. An anchor stores its coordinate system and provenance independently.

Run ingestion as a reproducible job: pin exports, normalize, check joins, diff releases, review anomalies, publish an immutable bundle. Start with directed breadth-first search; introduce weighted routing only when costs are defensible. Load details and sprites lazily, cache the shell, and retain a usable textual itinerary offline. Confirm reuse terms before distributing game assets at production scale.

8. Define “ready” with observable checks

  • Every route step resolves to a real map and directed portal; arrival names match. Hidden corridors expand into the exact underlying sequence.
  • Original art and route overlays share geometry. Decorative crossings never create graph junctions; schematic positions remain identified.
  • Every visible NPC/monster sprite joins by ID. Missing images show an honest fallback, never another creature.
  • At 320 px, controls remain reachable; keyboard, focus, screen-reader labels, contrast and reduced motion are checked.
  • Progress survives reload, stays isolated by character and can be undone. Unknown requirements never become false “available” badges.
  • Test the ten-map Lith–Henesys route, a hidden-map destination, reverse routes, disconnected destinations and export changes. Validate representative routes in-game before claiming runtime reliability.

Maple Atlas is an independent concept. MapleStory game names, data and character artwork belong to their respective owners. The original vector interface illustrates the product direction; source records and authored geometry have different levels of certainty.
